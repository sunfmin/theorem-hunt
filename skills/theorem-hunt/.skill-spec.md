# skill-spec: theorem-hunt

| Field | Value |
|---|---|
| name | `theorem-hunt` |
| description | Read existing code and find the "for every input" propositions it is supposed to obey; state each with its hidden precondition; sort into proof, property test, or design model; report a ranked list. Writes nothing. |
| target | dedicated repo `sunfmin/theorem-hunt` |
| visibility | public |
| needs | none bundled |

## functional_test

Task: run the hunt on a small fixture containing (a) `Move{lo, hi, dest}` with
`target(i)` and `inverse()`, where every caller first checks `isNoOp` and the
constructor accepts any three integers; a test named `testMoveBackRestores` with one
example; (b) `encodeColumn`/`decodeColumn`; (c) `mod(a, b)` implemented as
`a - b * round15(a / b)` beside a `gcd` whose comment says it avoids `mod` "because
the quotient rounds to 15 digits"; (d) `isEven`/`isOdd` built on `mod`; (e) a comment
"allocations always sum to the total" above a function using integer division.

Success condition, all must hold:

1. The report opens by saying entries are candidates and nothing is proven.
2. It lists the `Move` inverse proposition with the hidden precondition that the
   destination is not strictly inside the moved range, and notes that the constructor
   allows violating it.
3. It lists the column round trip.
4. It flags `mod` / `isEven` / `isOdd` with the 15-digit limit as the hidden
   precondition, citing the `gcd` comment as evidence.
5. It lists the allocation conservation proposition.
6. Each entry is sorted into Prove, Property-test, or Model, and at least one is
   Property-test.
7. Suspected mismatches are labelled by level of checking.
8. It ends with three things to do first.
9. No file in the fixture was modified.

## Provenance

Distilled from a five-module theorem hunt on a ~275k-line Swift codebase
(2026-10-09), which produced 112 candidates, most of them property-test candidates,
and several reproduced mismatches at numeric limits.
